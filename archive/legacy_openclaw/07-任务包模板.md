## B. 页面执行型任务包示例

### 1. 基本信息
- 任务编号：UI-TASK-EXEC-001
- 任务名称：跑腿发布链路 UI 第一轮产出
- 任务类型：页面执行型
- 当前阶段：页面执行
- 指派角色：执行 Agent
- 优先级：P0

### 2. 任务目标
完成小程序端跑腿发布主链路页面与核心状态页设计，确保后续可以进入审查阶段。

### 3. 范围定义
- 覆盖模块：跑腿
- 覆盖页面：发布入口、发布表单、提交成功页、订单详情页
- 覆盖状态：默认、校验失败、提交中、提交成功、无人接单、已接单
- 明确不包含：售后页、消息页、退款页

### 4. 输入材料
- 用户目标：优先完成跑腿主链路
- 依赖规范文档：页面树、状态矩阵、组件清单、命名规范
- 上游任务编号：UI-TASK-STRUCT-001

### 5. 输出要求
- 页面清单
- 页面说明
- 状态说明
- 交互说明
- 组件依赖说明
- 自检结果

### 6. 验收标准
- 页面不漏主链路
- 状态不缺关键节点
- 组件使用符合统一规范
- 页面说明足够支撑前端开发理解

### 7. 风险提醒
- 不得遗漏失败态与无人接单态
- 不得直接发明新组件绕过现有规范

### 8. 交接规则
- 自检通过后提交审查 Agent
- 如发现依赖页面缺失，立即上报主智能体

## C. 结构型任务包示例

### 任务编号：UI-TASK-STRUCT-001
### 任务名称：小程序端页面总表与状态矩阵梳理
### 指派角色：结构规范 Agent

#### 目标
完成小程序端前期 UI 范围内的页面盘点、状态矩阵、组件基础清单，为后续执行 Agent 派单提供统一地基。

#### 输出要求
- 页面总表
- 页面树
- 状态矩阵
- 组件清单
- 页面模板规则
- 小程序约束说明

#### 交接规则
- 完成后先交主智能体
- 主智能体审阅后再开放给执行 Agent 使用
