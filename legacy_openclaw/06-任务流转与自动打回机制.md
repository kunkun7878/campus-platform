# 任务流转与自动打回机制

---

## 1. 标准流转链路

用户提出目标
-> 主智能体解析需求
-> 主智能体生成任务树
-> 结构规范 Agent 产出地基
-> 主智能体生成任务包
-> 执行 Agent 产出
-> 执行 Agent 自检
-> 审查 Agent 独立审查
-> 通过则交主智能体合并
-> 不通过则自动打回执行 Agent
-> 修复后再次自检与复审
-> 通过后统一归档并向用户汇报

---

## 2. 自动打回触发条件

出现以下任一情况必须打回：
- 缺页面
- 缺状态
- 缺异常路径
- 缺交互说明
- 缺组件依赖说明
- 命名不统一
- 偏离统一规范
- 开发无法理解页面行为

---

## 3. 打回包必须包含的内容

- 原任务编号
- 打回结论
- 打回原因
- 具体缺失项
- 修复优先级
- 是否影响其他任务
- 复审标准

---

## 4. 合并前必须满足的条件

- 已通过执行 Agent 自检
- 已通过审查 Agent 审查
- 不存在未解决阻塞项
- 不与当前全局规范冲突
- 页面说明足以支持后续开发

---

## 5. 主智能体的合并责任

主智能体在合并前必须：
- 确认依赖项已满足
- 确认未遗留重要风险
- 确认当前轮产出范围清晰
- 确认可以向用户进行阶段性汇报
